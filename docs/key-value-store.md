# Key-value store

Not everything belongs in a managed [model](models.md) with a full state machine — session tokens, short-lived codes,
cached blobs, and similar opaque values are often simpler to store directly. Klerk provides a built-in key-value store
for this, available as `klerk.keyValueStore`.

Keys are always generated by Klerk — you never choose your own key. `put(...)` returns a typed id (`StringKeyValueID`,
`IntKeyValueID`, or `BinaryKeyValueID`), which you hold on to and pass to `get(...)` later.

```kotlin
val id: StringKeyValueID = klerk.keyValueStore.put("some value")
val value: String = klerk.keyValueStore.get(id, context)
```

```kotlin
val id: IntKeyValueID = klerk.keyValueStore.put(42)
val value: Int = klerk.keyValueStore.get(id, context)
```

`get` throws `NoSuchElementException` if there is no value for that id (wrong id, or it has expired).

## TTL

`put` takes an optional `ttl: Duration?`. If provided, the value expires `ttl` after the moment it was stored. A `get`
for an expired value throws `NoSuchElementException`, same as a missing id. If `ttl` is omitted, the value never expires
on its own.

## Blobs

Storing a blob (`InputStream`) is a two-step process instead of a single `put`:

```kotlin
val token: BlobToken = klerk.keyValueStore.prepareBlob(inputStream)   // 1. upload
val id: BinaryKeyValueID = klerk.keyValueStore.put(token)             // 2. finalize
val value: InputStream = klerk.keyValueStore.get(id, context)
```

The reason for the split is that `prepareBlob` is a plain (non-suspending) function that writes the blob to storage
without acquiring Klerk's read/write lock. Large uploads can take a while, and Klerk doesn't want that upload to block
command processing or reads for the rest of the application. Once the upload finishes, the cheap `put(token)`
step marks the blob active and (optionally) sets its TTL.

A blob is **not** retrievable between the two steps — `get` on a id derived from a fresh `BlobToken` throws
`NoSuchElementException` until `put(token)` has been called:

```kotlin
val token = klerk.keyValueStore.prepareBlob(data)
klerk.keyValueStore.get(BinaryKeyValueID(token.id), context) // throws NoSuchElementException
klerk.keyValueStore.put(token)
klerk.keyValueStore.get(BinaryKeyValueID(token.id), context) // now returns the data
```

`prepareBlob` internally gives the pending blob a 5-minute TTL on its own, so an upload that's never finalized with
`put(token)` doesn't linger forever.
